# Agent guidance — QMS_demo vault

This vault is the **guide half** of the QMS demo. Controlled documents live in the separate `qms-controls` repository. Files are the source of truth; edit them directly. Read `lessons-learned.md` and `DEVELOPMENT.md` before extending the build.

## Scope

- Only `guides/` and `index.md` are published by this site. `site/.vitepress/publish-scope.mjs` is the single source of truth; do not change scope in three places.
- The vault root is `qms-vault/vault/`. Website code, scripts and the deploy workflow stay at the repository root, outside the vault, so Tolaria's Inbox stays clean.
- Links to notes held by `qms-controls` resolve through `site/.vitepress/remote-manifest.json` to absolute URLs. Keep that manifest current when filenames change there.
- The two repositories are independent: never import code from the other one.

## Website rules

- Never alias the `vue` package in `config.mts`; it creates two Vue instances and kills hydration. `docs:prepare` creates a `node_modules` symlink **inside `vault/`**.
- Never write literal double-curly-brace expressions or angle-bracket placeholders in Markdown prose.
- `sidebar.json` is generated by `build-sidebar.mjs`; never hand-edit it. The sidebar uses numeric guide prefixes (`01` → `01.2` → `01.2.1`), so keep numbering in filenames meaningful.
- Mermaid source travels in a base64 `data-source` attribute; VitePress collapses literal newlines in raw HTML. Every rendered diagram gets an **Expand overview** overlay.
- Sidebar type is intentionally small (~14px chapters, ~13px sections, ~12px details). Do not enlarge it.
- The hide-navigation control uses `nav-bar-content-before`; `nav-bar-title-after` is inside the title anchor and would navigate home.
- Cross-site links use the `wikilink-remote` class and open in a new tab; excluded notes use the dimmed "not published" marker.
- After any site change, run `npm run docs:build` and test the sidebar, theme switch and diagrams in a browser.

## Authoring rules

- Every note needs `type:` frontmatter. Valid values are defined by Type notes, but this vault only holds `Note`-type guides; the full QMS taxonomy lives in `qms-controls`.
- Use double-bracket wikilinks. Within the vault, links resolve by filename stem or H1 title.
- Keep frontmatter minimal: `type`, `status`, `tags`, and the fields a guide actually needs. Put narrative in the body.
- Only a human may set `status: active`. Agents create `draft` notes and prefix such commits with `chore(ai):`.
- Guides are onboarding material, not controlled documents — do not invent `doc_id` or `revision` for them.

## Validation

```sh
python3 scripts/validate-vault.py
python3 scripts/validate-wikilinks.py
(cd site && npm run docs:build)
```

The four frontmatter notices (`AGENTS.md`, three untyped captures in the other vault) are historical; cross-site links are accepted through the remote manifest.
